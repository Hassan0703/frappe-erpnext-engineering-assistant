# 2.0.0-beta.1 — Frappe ERPNext Engineering Assistant (preview)

**Released:** 2026-10-19
**Status:** preview. Usable today; not a stability guarantee.

## What this is

An independent, professionally branded engineering assistant for Frappe Framework and ERPNext v15
and v16. It turns an AI coding agent into a more disciplined Frappe engineer: find the owning app
first, extend through supported mechanisms, keep business rules on the server, and show evidence
before reporting a task as done.

## Highlights

**A new identity.** The product, skill, plugin, and marketplace were renamed. The MIT copyright and
permission notice are preserved, and `NOTICE` records the provenance. Existing installations must be
removed and reinstalled — the identifiers changed, so an in-place upgrade is not possible.

**White-labeling as a real workflow.** Discovery, a five-class safe-change decision tree, the full
surface inventory (desk, login, website, portal, email, print/PDF, assets, translations, app tiles),
verification, and an upgrade regression checklist. Branding guidance is explicit about what belongs
in a custom app, what is configuration, and what is a framework fork of last resort.

**Evidence levels you can rely on.** Every version-sensitive claim is labelled runtime-verified,
source-verified, documentation-verified, or unverified. Two claims were corrected in this release
after re-checking the installed v15 and v16 source: `app_icon` / `app_color` are not consumed by
Frappe core for the app tile, and `get_translated_dict` is deprecated in v16 rather than removed.

**Delivery work, not just coding rules.** ERP implementation, data migration and reconciliation,
deployment and operations, testing and QA, security, AI-assisted development, and incident support —
each with a reference that owns the topic and templates you can fill in.

**Safer production changes.** A four-class risk classification ties each change to its required
backup, approver, window, and rollback expectation. Permissions and authentication changes are class
4 by default.

**A release gate that fails.** The repository validator now checks branding, reference and template
inventory, links, unsupported version phrasing, secrets, and local paths. The bundled templates are
verified byte-identical to the canonical copies. 28 tests exercise the validator's passing and
failing cases, and CI runs all of it.

## Install

```bash
claude plugin marketplace add Hassan0703/frappe-erpnext-engineering-assistant
claude plugin install frappe-erpnext-engineering-assistant@frappe-erpnext-assistant
```

Other agents can copy the skill folder into their skills directory; see the README. Claude Code is
the only packaged integration tested.

## Upgrading from the previous name

```bash
claude plugin uninstall frappe-code-standards@nextash
claude plugin marketplace remove nextash
claude plugin marketplace add Hassan0703/frappe-erpnext-engineering-assistant
claude plugin install frappe-erpnext-engineering-assistant@frappe-erpnext-assistant
```

Update any project instruction file that names the old skill.

| ERPNext v16 | Yes (matching major) | Source-verified |
| Frappe v15 | Yes | Source-verified on 15.94.1; not executed |
| ERPNext v15 | Yes (matching major) | Source-verified |
| v14 and earlier | No | — |

## What was verified, and what was not

**Verified:** repository structure, links, template parity, manifests, workflow YAML, script syntax,
secret/branding/path scans, 28 validator tests, and the source-level checks listed in the Phase 3
audit.

**Not verified:** v15 runtime execution, scheduler and workers, email delivery, PDF rendering, and
GitHub Actions at the time of the release decision. No live agent evaluation was run, so no scenario
is claimed as passed. Exact branding fieldnames still depend on the installed patch level.

See `docs/audit/phase-3-release-audit.md` for the full gate table and remaining limitations.
